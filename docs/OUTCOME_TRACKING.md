# Outcome Tracking v0.1

## Purpose

Outcome Tracking closes the first measurable learning loop:

```text
state
 ↓
decision
 ↓
action
 ↓
expected outcome
 ↓
wait observation horizon
 ↓
actual outcome
 ↓
residual / error
 ↓
Historian
```

It measures prediction quality. It does not yet retrain a model automatically.

## Expectation

An expectation references the same correlation ID as the originating decision.

It defines:
- metric component
- canonical metric point
- observation horizon
- expected absolute value **or** expected delta from baseline
- optional tolerance
- unit
- optional Learning Model ID/version

Example:

```text
correlation: A17
metric: buffer.thermal.temperature_upper
baseline: 50.0 °C
horizon: 3600 s
expected delta: +7.0 K-equivalent temperature change
expected value: 57.0 °C
tolerance: 1.5 °C
model: buffer_thermal v1
```

## Observation

At/after the due time, Outcome Tracker reads the freshness-aware StateStore.

Example result:

```text
expected 57.0 °C
actual   55.8 °C
residual -1.2 °C
absolute error 1.2 °C
within tolerance true
```

The expected and observed events are persisted in Historian under the same correlation ID.

## Unobservable outcomes

If the required result point is:
- missing
- STALE
- INVALID
- UNAVAILABLE

the result is:

```text
UNOBSERVABLE
```

INS-EI must not convert missing evidence into a training sample.

This distinction is important for Learning readiness: many actions with unobservable outcomes are not evidence that a model is accurate.

## Model versions

Expectations can identify the model/version that made the prediction.

This allows later questions such as:
- How accurate was buffer model v3?
- Did battery-efficiency model v5 improve residuals?
- Did accuracy deteriorate after a component change?

## API

Register expectation:

```text
POST /outcomes/register
```

Evaluate due outcomes:

```text
POST /outcomes/evaluate
```

Trace the whole chain:

```text
GET /history/trace/{correlation_id}
```

## Next step

Outcome expectations should increasingly be generated by Strategies/Learning Models automatically rather than manually registered.

After that, a Model Registry can aggregate residuals and derive Learning Readiness/confidence from real prediction performance.
